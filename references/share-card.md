# 方形运动分享卡

## 目标

把一次训练压缩成一张适合朋友圈的 1:1 图片：照片保留现场感，GPS 轨迹保留行动痕迹，距离、心率和一句话解释保留当天最值得记住的信息。

卡片不是完整报告。详细指标、三信号和历史表格留在 `report.html`。

## 固定数据顺序

```text
原始 GPS
→ privacy_trim（fail-closed）
→ 0..1 局部 XY 路径
→ 透视投影
→ SVG / Pillow
```

`card_visual.py` 只接收局部 XY，不能接收经纬度。短路线或裁剪为空时返回 `fully_hidden`，不允许恢复原始路线。

隐私状态：

- `trimmed`：显示“起终点已隐藏”；
- `fully_hidden`：显示“路线因隐私保护未展示”；
- `off`：显示“隐私模式已关闭”；
- `no_route`：显示“本次无 GPS 轨迹”。

## 照片处理

1. 接受 JPEG、PNG、HEIC/HEIF。
2. 使用 `ImageOps.exif_transpose()` 处理 iPhone Orientation。
3. 转为 RGB，按方形画布 center-cover 裁切。
4. 重新编码为 PNG bytes，不传递 EXIF、GPS、设备型号或原始文件路径。
5. HTML 使用 data URL；Pillow 从净化 bytes 解码。
6. 不重绘、不扩图、不美颜、不移除或新增人物与物体。

自动去元数据不能隐藏照片画面中的门牌、地标、人物或家庭环境。分享前仍需人工确认画面。

## 透视规则

路线透视是确定性的视觉投影：

- 上边收窄到较远的画面平面，下边较宽；
- 深度方向使用非线性压缩；
- 保持点顺序、分段与路线拓扑；
- 不用海拔生成虚构地形；
- 不绘制道路、建筑、地图瓦片或地点名称；
- 起终点标记只对应隐私裁剪后的安全端点。

它不是导航路线规划，也不代表真实三维地图。

## 视觉约束

- 1080×1080 画布，2x 输出 2160×2160；
- 照片是第一视觉焦点；无照片时路线成为主角；
- 只使用一个强调色，路线下方增加中性底线保证可读；
- 不使用霓虹外发光、AI 紫色渐变或四个等宽指标卡；
- 距离是主数字，平均心率为第二层级；
- 时长与配速只作辅助；
- 一句话最多两行；
- 在约 390px 手机缩略图下仍需读清距离和平均心率。

## 失败方式

- 显式照片路径不存在或图片损坏：返回非零，不静默降级。
- HEIC 解码依赖缺失：提示运行 `./setup.sh`。
- Chrome 截图不可用：`auto` 模式回退到 Pillow。
- 隐私裁剪无法产生安全路径：隐藏路线，但仍可生成照片卡。

## 测试底线

- 最终 PNG 为 2160×2160；
- PNG 无 EXIF/GPS；
- HTML 不含原始照片绝对路径和经纬度；
- 短路线与全裁空路线不回退原坐标；
- HTML 与 Pillow 使用同一份 SafeCardSpec；
- 透视前后点序和分段保持一致。
